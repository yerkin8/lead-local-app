# 01 — переписывание скриптов первых сообщений

Путь: bounded (поток импорта скриптов уже есть — `app/import_scripts.py`). Владелец недоступен,
решения приняты по его требованиям.

- Источник текстов: `app/script_texts.py` (`TEXTS`, slug → (название, текст)); таксономия —
  `app/script_templates.py`. 97 скриптов, 35 первых (`*.first*`). Подстановка одна: `{название}`;
  поля `[…]` правятся вручную перед отправкой.
- В базу тексты попадают через `db.sync_builtin_templates`: обновляется только строка, чей текст
  совпадает с `default_hash` (пользователь не правил); правленые не трогаются.
- Подпись — `outreach.OPT_OUT_FOOTER`, ссылка «Написать» — `t.me/…?text=` + `quote()`, лимит 2048.
  Кириллица кодируется по 6 знаков, поэтому реальный лимит ссылки ≈ 290 символов текста.
  Решение: длинные тексты допустимы (работает «Копировать», K4), импортёр предупреждает отдельно
  о > 1800 символов с подписью и о превышении ссылки; в промпте цель 450–800 символов.
- Формат обмена — тот же, что читает `app.import_scripts` («### `slug` — Название» + ```text),
  плюс строка «Назначение» и заголовки этапов (игнорируются парсером).
- `scripts/import_rewritten_scripts.py`: `--export` выгружает; импорт строгий (все slug-и, без
  чужих, подстановки совпадают), dry-run по умолчанию, `--apply` пишет через
  `import_scripts.apply` (уважает default_hash).
- Тексты не менялись. Тест: `tests/test_import_rewritten_scripts.py`.
