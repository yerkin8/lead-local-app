# 02 · Рассылка пачкой из «Лидов», автоподстановка, правка текстов

Запросы владельца: 1.1 «персонализировать сообщения перед отправкой»; 2 «кампания строится в "Лидах"».
Уточнение владельца: «раздел рассылка остается … это происходит ПАЧКОЙ имеющихся лидов. каждому самостоятельно
подставляется сообщение и по одной кнопке я запускаю рассылку (в настройках менять тайминг и количество)».
Первый вариант (выбор лидов галочками по одному) отменён и в коммит не вошёл.

## Поток владельца
1. «Лиды» → вкладка (Новые/Напомнить/…) и фильтры (ниша, город, поиск, тип сайта) → «Разослать этой пачке».
2. Экран «Рассылка по пачке лидов»: число получателей (не больше «Лидов в одной пачке» из настроек),
   скрипт «Авто: под тип сайта лида» (по `FIRST_BY_SITE_TYPE`) или конкретный, аккаунты (готовые отмечены),
   слово `ОТПРАВИТЬ` и одна кнопка «Запустить рассылку».
3. Необязательно: «Сначала посмотреть тексты» — черновик (сухой режим) со списком итоговых сообщений; любое можно
   поправить («Сохранить текст») и вернуть шаблон. Дальше как раньше: сухой запуск / реальная отправка.
4. «Рассылка» остаётся: аккаунты, ключи, кампании, статус, история, стоп-лист, журнал, «Новая кампания» по фильтрам и тестовая.

## Устройство
- `MailingService._select`: фильтр `ids` (до 500, порядок сохраняется); без username → «пропущено: Нет username Telegram».
- Шаблон `auto`: каждому получателю — первый скрипт под его `site_type`.
- `MailingService.launch(title, ids, template, accounts, confirm)`: проверка слова и аварийного стопа до создания →
  кампания → `enable_live` → `run`. Лимиты, окно, паузы, стоп-лист, карантин — те же, что у любой кампании.
- `set_message` / `reset_message`: только пока кампания не идёт и получатель `queued`/`dry_sent`; без [скобок];
  строка «СТОП» всегда. Колонка `recipients.edited` добавляется `ALTER TABLE` при открытии.
- `Policy.batch_limit` (1–500, по умолчанию 100) рядом с паузами и лимитами; все границы жёсткие (`Policy.LIMITS`).
- Мост: `mailing_launch`, `mailing_message_set`, `mailing_message_reset`.
- `mailingSettingsBlock(node)` (mailing.js, `window.mailingSettingsBlock`) — самостоятельный блок «Рассылка: тайминг и
  количество» для экрана «Настройки» (монтирует владелец экрана настроек), сохраняет сам.
