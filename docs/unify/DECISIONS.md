# Решения переноса Mini App → Desktop

| # | Решение | Альтернативы | Причина | Источник |
|---|---|---|---|---|
| U1 | Основа — DESK: его оболочка, светлый дизайн, `main()` окна, сборка, рассылка. Из MINI берётся механика | переписать DESK на интерфейс MINI | В DESK исправлено зависание при запуске (в MINI его нет, MINI desktop.py:457-459), есть сборка и рассылка, а светлый дизайн — требование владельца | отчёт агента UI, коммит 9993340 |
| U2 | Перенос трёхсторонним слиянием с базой = первая версия MINI | ручное переписывание экранов | База совпадает с DESK построчно (PARITY.md), значит различие = изменения MINI, и их можно применить с доказуемой точностью | `diff --strip-trailing-cr`, verification/unify |
| U3 | Транспорт `LEM.invoke` из MINI вместо прямого `bridge()`; HTTP-сервер в десктопе не поднимается | своё JS-API для DESK | Модули MINI переносятся без правок; `onReady` один раз устраняет перерисовку при повторном `pywebviewready` | transport.js:97-129; edgechromium.py:385-389 |
| U4 | Реестр `services` подключается к `Bridge` циклом с `hasattr`. Методы DESK, которые MINI удалил из класса (`business_save`, `templates`, `business_scripts`, `stats` и др.), удаляются вслед за MINI. Важнее реестра остаются только `DESKTOP_ONLY` и `MailingBridgeMixin`. Серверные методы исключены списком `SERVER_ONLY` | оставить методы DESK главнее | Иначе `hasattr` прячет версии MINI: «Позвонить», 4 предложения и таксономия не заработают (разбор, п. 3) | MINI desktop.py:358-367, services.py:355-376 |
| U5 | Новая версия схемы — 7, и перед миграцией делается резервная копия | оставить 6 | В реальной базе DESK уже стоит v4 из ветки 183745, а v4 в MINI значит другое. С 7 копия перед миграцией гарантирована | отчёт агента данных |
| U6 | Приложение отказывается открывать базу новее себя и показывает понятное сообщение | падать | Старая сборка DESK на v6 падает с OperationalError | прогон C агента данных |
| U7 | `FIRST_BY_SITE_TYPE` остаётся и указывает на новые slug | правка рассылки | Рассылку трогать нельзя; она читает это имя | mailing/desktop_bridge.py:17 |
| U8 | Заметки убраны из интерфейса, колонка в базе остаётся | оставить заметки | Явное решение владельца в этом чате («убрать полностью "заметки"»); данные не удаляются | docs/rewrite/PLAN.md решение 2 |
| U9 | Ключ OpenRouter хранится в DPAPI текущего пользователя и вводится в настройках или мастере; переменная окружения — только для разработки | переменная окружения | В архиве для других людей у каждого свой ключ; переменная окружения не подходит для zip | mailing/protect.py:54-96 |
| U10 | Не переносится серверное: admins, bot_chats, HomeAgent, серверный worker, ночная очистка копий, package_gallery | перенести всё | В локальном приложении эти механики не нужны, а очистка удалила бы ручные копии (`lem-*`) | maintenance.py:38-46 |
| U11 | Чипы фото, капча при каждом запуске и `input()` в оригинальных парсерах в перенос не входят — они в KNOWN_ISSUES | чинить сейчас | Код в MINI и DESK одинаков, перенос их не закрывает; по постановке такие проблемы фиксируются, а не чинятся по отдельности | отчёт агента парсинга |
| U13 | Рассылка перестаёт брать скрытых («удалённых») лидов: так работает `list_businesses` из MINI. Совместимый `FIRST_BY_SITE_TYPE` получает ключи `''` и `other` → `site.first`. В выпадающем списке скриптов рассылки 97 строк вместо 20 — записано в KNOWN_ISSUES, рассылку не трогаем | патчить рассылку | Скрытый лид — это решение пользователя не работать с ним; править рассылку запрещено | разбор, п. 8; mailing/service.py:336 |
| U14 | Стартовый экран — «Панель» DESK. Форма поиска — DESK, туда добавляется «отзывов от N». Страница поиска из leads.js и хаб «Ещё» не переносятся. «Итоги» — часть раздела «Лиды». Клик по строке «Лидов» открывает карточку лида, по строке «Базы» — карточку организации с 4 предложениями | взять навигацию MINI | В DESK боковое меню, которому хаб «Ещё» не нужен; форма поиска DESK привычна владельцу | разбор, п. 7; leads.js:488 |
| U15 | Все запуски при разработке и проверке — только с `DATA_DIR` во временной папке. Реальная база переводится на v7 один раз, на шаге 4.5 после приёмки, с откатом из `backups\app-pre-schema-v7-*` | запускать на реальной базе | После v7 старая сборка на реальной базе не стартует | разбор, п. 4 |
| U16 | Тесты запускаются интерпретатором `parserYand\.build-venv` (Python 3.14.8, зависимости из `requirements-exe-lock.txt`, в том числе phonenumbers 9.0.41) | `.venv` | В `.venv` нет phonenumbers, который после переноса нужен при старте | разбор, п. 9 |
| U12 | «Сегодня» переносится, при этом не связан с лимитами рассылки | объединить политики | Рассылку трогать нельзя; «Сегодня» — ручная отправка по ссылкам, а рассылка — автоматическая; это два разных сценария | outreach.py, mailing/policy.py |
| U17 | Ключ OpenRouter: `app/secret_store.py` — DPAPI текущего пользователя, соль `LeadEqualMoney.ai.v1`, файл `%APPDATA%\LeadEqualMoney\ai\openrouter.bin`, папка закрыта icacls. Ввод в «Настройках» → «ИИ-чат» и необязательным полем мастера первого запуска; читается на каждом вызове (без перезапуска); переменная `OPENROUTER_API_KEY` важнее (разработка). Ключ не возвращается странице, маскируется (`sk-or-v1-***`) в сообщениях | переменная окружения; общий файл с рассылкой | Zip для других людей: у каждого свой ключ; файлы рассылки не трогаем (своя соль и файл) | mailing/protect.py (идея), tests/test_ai_key.py |
| U18 | Пустая таблица `admins` создаётся в базе Desktop общим `init_db` Mini App; серверный код, который её использует, не переносится (U10) | вырезать таблицу из схемы | Безвредна; та же схема БД у обоих продуктов упрощает импорт и замену базы | независимая приёмка, замечание 4 |
