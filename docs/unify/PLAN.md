Общие проверки после каждой волны:

- 39 тестов рассылки;
- `hash_manifest.py` по защищённым файлам: совпадает с `hashes-before.json`.

   - миграция копии реальной базы DESK (40 организаций, v4) и ночной копии MINI: v7, повторный запуск ничего не меняет, число строк по таблицам совпадает, правки пользователя сохранены.

## Волна 3 — ключ ИИ и мастер первого запуска (строка 14)

1. Новый `app/secret_store.py`: DPAPI для текущего пользователя, папка `%APPDATA%\LeadEqualMoney\ai`. Идея взята из `mailing/protect.py`, сам файл не меняется.
2. Ключ берётся по порядку: сначала переменная окружения (для разработки), затем файл DPAPI. Он читается при каждом вызове, поэтому после сохранения перезапуск не нужен.
3. В «Настройках» появляется поле ключа, в мастере первого запуска — необязательный шаг. Ключ никогда не возвращается на страницу.
4. Маскирование `sk-or-v1-…` в логах ИИ-модуля. Скан утечек проверяет и `key.txt`.

## Волна 4 — сборка и приёмка

1. `build.ps1`, затем скан утечек сборки и zip, затем «чистая машина» через мастер.
2. Окно должно отвечать в 5 запусках подряд. Запуск из другой папки и по ярлыку.
3. Сквозные сценарии в собранном приложении на копии данных:
   - поиск (HTTP, на фикстуре и одним живым запросом к yandex.ru);
   - фото, товары;
   - список и карточка;
   - подсказки, ИИ-чат на заглушке плюс 1 живой запрос;
   - статистика.
4. Независимый агент проходит `ACCEPTANCE.md` и выносит вердикт.
5. Обновление ярлыка и сборки на рабочем столе — только после приёмки. Старая сборка уже сохранена в бэкапе.

## Изменения после независимого разбора (31.10)

Разбор нашёл 3 блокера, 7 серьёзных и 6 мелких замечаний. Все приняты, в этот план внесены:

1. **Волна 1 делится на две.**
   - 1a: самостоятельные модули, `db.py`, `script_templates` с совместимостью, тесты миграции; `desktop.py` не трогается.
   - 1b: реестр `services` и слияние `desktop.py`. В конце 1b — `build.ps1` и `smoke_staged_exe.ps1` на временной `DATA_DIR`, чтобы ошибки импорта в собранном exe всплыли сразу.
2. **`services.py` переносится без серверного блока:** без `admins` и без методов `whoami`, `admins_*`, `export_send`, `backup_send`, `agent_settings*`.
   - Шлюз: `import app.desktop` проходит, и ни одно имя из `SERVICES` не тянет `admins`, `bot` или `agent`.
3. **`desktop.py`: `main()` берётся из DESK** (9993340), из MINI — только `services.bootstrap()` и цикл реестра.
   - Шлюз: grep по `agent|HomeAgent|home_agent|admins|from .bot` пуст.
   - Тест покрытия: методы `Bridge` = `DESKTOP_ONLY` + `bootstrap`.
4. **Тесты MINI переносятся с перечисленными правками:**
   - случай с `agent` в test_min_reviews пропускается;
   - test_script_taxonomy требует `import_scripts.py` — его копируем как инструмент разработчика, в сборку он не попадает;
   - test_services учитывает методы `MailingBridgeMixin`;
   - `WEB_METHODS` и серверный zip для бота не проверяются.
5. **После каждой волны — полный `scripts\verify.ps1`.** `check_desktop_telegram_surface.py` обновляется в 1b: учитывает реестр и новые JS-файлы.
6. **Интеграция с рассылкой проверяется отдельным тестом.** `create_service()` на мигрированной копии базы:
   - `preferred` из `script_suggestions` есть среди скриптов для каждого типа сайта (`''`, `no_site`, `weak_site`, `unavailable`, `other`);
   - скрытые и стоп-лист не выбираются (решение U13).
7. **Волна 2.**
   - leads.js: убрать `search` из `PAGES`, стартовый экран оставить DESK, `[data-search-results]` не перехватывать (решение U14).
