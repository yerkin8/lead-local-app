## Задачи (в этом порядке)

### 1. Все номера телефонов из карточки (главное)
Факт (01.11, «Гранат», https://yandex.ru/maps/org/granat/1011865976/): в HTML карточки виден 1 номер
(городской +7 8332…), второй (мобильный +7 912…) скрыт за «1 ▾»; в JSON состояния той же страницы
(`script.state-view` → `stack[0].results.items[0].phones[]`, поля `type/number/value`) — **оба**. Нажимать на стрелку
не нужно. Мобильный также есть в ссылке WhatsApp карточки (`wa.me/79127…`).
* `app/lead_parser.py` `parse_org_html`: телефоны = HTML ∪ JSON состояния (`phones[].value`/`number`) ∪ номера из
  ссылок `wa.me/<цифры>` и `viber` (если есть), нормализовать (`app/phone_links.py`), убрать дубли, порядок:
  как на карточке. Запасной путь — только HTML.
* Карточка лида показывает все номера; для каждого мобильного — «Telegram по номеру» (это уже делает
  `outreach.contacts` → `build_telegram_phone_links`, городские отсекаются).
* Существующие лиды: кнопка/фоновое задание «Дособрать номера» для лидов, где сейчас 1 номер или нет мобильного
  (по одному запросу на карточку, паузы как в поиске, остановка, капча = статус). Сначала проверь на копии базы.
* Тесты на фикстуре с двумя номерами в JSON и одним в HTML; живая проба на «Гранате» (1 запрос).

### 2. Одна карточка лида везде (баг)
Сейчас из «Лидов» открывается новая карточка (`leads.js`, вид `lead`), а из «Сегодня» → «Карточка», из
«Рассылки» (кнопка «Карточка» у получателя), из результатов поиска — **старая** (`data-open` →
`setView('detail')`: `app.js` `detail` + переопределение в `stage9.js`, «Карточка организации · данные…»).
* Все `data-open` ведут в вид `lead` (единая карточка). Старый вид `detail` удалить (app.js/stage9.js/flows.js
  `detail`), ссылки на него перевести.
* Перенести в новую карточку то, чего в ней нет: «Медиа», «В «Сегодня»», «Обновить с Яндекс.Карт»
  (сервис `business_refresh` есть, кнопки в новой карточке нет), все телефоны, ссылки и соцсети,
  режим работы/особенности/отзывы (как в блоках ниже карточки).
* `← Пред. / След. →` при открытии не из «Лидов»: по очереди «Сегодня» (из «Сегодня») или скрыть.
  «Назад» возвращает туда, откуда пришёл (`← К «Сегодня»`, `← К рассылке`).
* Ссылки `wa.me/…?text=…` не показывать сырым закодированным URL: подпись «WhatsApp» + номер.
* Обход окна: из «Сегодня», «Рассылки», результатов поиска открывается `state.view === 'lead'`, старого вида нет.

### 3. «Добавить лида» по ссылке и свои номера/ссылки в карточке
* Кнопка «Добавить лида» в «Лидах»: поле для ссылки на организацию Яндекс.Карт (любой вид: с `?ll=…`,
  `yandex.com`, короткие `yandex.ru/maps/-/…` — раскрыть редиректом). Дальше тот же разбор, что у поиска
  (карточка, проверка сайта, все номера, отзывы по лимиту из «Настроек», число фото) — фоновым заданием со
  статусом и «Остановить»; город — из адреса, ниша — из рубрики (можно поправить). Если лид уже есть — открыть его.
  Тип сайта не фильтровать (владелец сам решил добавить).
* В карточке лида: «Добавить номер» и «Добавить ссылку» (t.me, сайт, соцсеть). Хранить отдельно от данных парсера
  (например, таблица `manual_contacts`), чтобы «Обновить с Яндекс.Карт» их не стирал; показывать вместе с
  найденными, с пометкой «добавлен вручную»; участвуют в «Написать в Telegram» и в рассылке (username из t.me).
  Номер схемы: если нужна новая версия — 8, и записать в KNOWN_ISSUES, что ветке 183745 тогда нужна ≥ 9 (K7).
* Тесты: разбор ссылки (варианты URL), дубль, ручной номер переживает обновление карточки.

### 4. Один ползунок прокрутки (баг)
На карточке справа два ползунка: `.main` в `style.css` — `height:100vh; overflow:auto`, и при этом прокручивается
документ (что-то выходит за 100vh). Нужна одна прокрутка: либо `html, body {height:100%; overflow:hidden}` и
прокручивается только `.main`, либо наоборот — без `.main` со своим `overflow`. Проверить все разделы в
светлой/тёмной теме и при узком окне; в обходе окна — проверка
`document.scrollingElement.scrollHeight <= innerHeight` (нет второй прокрутки).

### 5. Кликабельная ссылка в рассылке
Факт: `app/mailing/telethon_gateway.py` шлёт `SendMessageRequest(…, text, no_webpage=True)` без `entities`, поэтому
`(https://alivolya.online)` у получателя — обычный текст (из своего клиента Telegram ссылка подсвечивается сама,
поэтому в «Сегодня» проблемы нет).
* Добавлять `entities`: `MessageEntityUrl` для каждого URL в тексте (смещения в UTF-16!) — ссылка в скобках
  становится рабочей. Разметка `[слова](https://…)` в скрипте → `MessageEntityTextUrl` (гиперссылка в словах),
  в тексте остаются только слова. Для первого сообщения владелец согласен на видимую ссылку.
* `FakeGateway` сохраняет entities; тесты на смещения с кириллицей и эмодзи; `no_webpage` остаётся.
* Живая проверка: одно сообщение с тестового аккаунта тестовому адресату, ссылка кликабельна.

### 6. «Тесты» в рассылке
* Отдельная кнопка/вкладка «Тесты»: список тестовых адресатов (добавить/убрать username; сейчас — только загрузка
  из файла `accounts.local.json`), тестовый аккаунт, «Запустить тест» на пачку из «Лидов» (тексты реальных лидов,
  доставка тестовым адресатам).
* Тест идёт **по той же схеме, что бизнесы**: окно 10–19, паузы, лимиты. Сейчас `engine.earliest_send` для тестовых
  получателей окно пропускает (`tz` пустой) — дать тестовым адресатам часовой пояс владельца (Москва) и
  применять окно. Переключатель «Без ожидания» — только для быстрой проверки доставки (явно подписан).
* Везде, где показано время отправки (сухой запуск, получатели), писать: «уйдёт в 10:00 по Тюмени (08:00 МСК)».
* Тесты: окно для тестовых получателей, «без ожидания», отображение двух времён.
