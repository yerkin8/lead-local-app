## Задача 1. Поиск слишком медленный

Факты от владельца: цель 30 организаций в одном городе; поиск запущен в 01:35, к 01:40 просмотрено 22 карточки; раньше бывало 3 карточки в минуту. Это слишком мало.

Что известно по коду: `app/lead_parser.py`, `run_search()` сейчас вызывает `run_search_http()`. На каждую карточку идёт несколько последовательных HTTP-запросов: страница организации, отзывы (по умолчанию 20, «Отзывы на организацию» в форме; постранично с паузами `random.uniform(0.5, 1.0)`), число фото галереи, проверка сайта (`fetch_site`, таймауты 5/12 с). Есть и `run_search_browser()` (Selenium).

Нужно:
- Сначала **замерить**, куда уходит время на одну карточку (по этапам), на небольшом живом прогоне и/или на фикстуре. Записать замеры.
- Ускорить в разы. Цель — не меньше 15–20 карточек в минуту при отзывах = 0 и заметное ускорение при отзывах > 0. Варианты (выбрать по замерам): как в оригинальном `yandex_parser_fixed.py` — открыть вкладку браузера, прокручивать список выдачи и разбирать карточки (владелец считает этот путь намного быстрее); вынести отзывы и галерею из основного прохода (догружать позже или при открытии карточки); ограниченная параллельность; переиспользование сессии/драйвера; проверка сайтов параллельно с короткими таймаутами.
- Кандидаты на исправление уже есть в ветке `claude/leadequalmoney-yandex-parser-183745`: постоянный профиль браузера (капча при каждом запуске, K2), поиск чипов фото по тексту (K1), ожидание капчи (K3), отмена задания. Посмотри и перенеси то, что подходит (с учётом K7 — номер схемы).
- Капча и блокировки должны по-прежнему давать понятный статус задания «капча», а не ошибку.

## Задача 3. Что происходит с пачкой после рассылки и повтор рассылки

Как сейчас (проверь сам): рассылка по пачке создаётся из «Лидов» кнопкой «Разослать этой пачке»; кампания и её получатели хранятся в `%APPDATA%\LeadEqualMoney\mailing\mailing.sqlite3` (таблицы `campaigns`, `recipients`, `attempts`) и видны в «Рассылка» → «Кампании». Статусы лидов в «Лидах» рассылка не меняет. Повторить кампанию с другим сообщением и убрать получателя из кампании нельзя — только удалить кампанию целиком.

Нужно:
- Объяснить владельцу простыми словами, что является результатом рассылки (где пачка, что видно по каждому бизнесу), и сделать это понятным в интерфейсе: у каждой кампании — список бизнесов пачки с результатом по каждому (отправлено / не дошло / в стоп-листе / пропущено).
- **Повтор пачки с другим сообщением** одной кнопкой: например, «Напоминание» (скрипты этапа follow-up), тот же состав пачки, тексты подставляются сами, запуск так же одной кнопкой с подтверждением.
- **Убрать бизнес из пачки** (например, уже ответил), чтобы он не попал в повторы. Предложи и сделай разумное автоисключение: бизнесы, которые в «Лидах» уже «Ответили» / «В работе» / «Договорились» / «Отказ», в повтор не попадают по умолчанию.
- Решить (через brainstorming) и сделать связь со статусами «Лидов»: после успешной отправки лид получает «Написал» и попадает в напоминания, как при ручной отправке.
- Не ослаблять защиту рассылки: слово подтверждения, аварийный стоп, стоп-лист, «Не писать», лимиты, FloodWait, карантин, строка «СТОП».
- Тесты на повтор, исключение, связь со статусами.

## Задача 4. Живая проверка рассылки

- Реально отправлять можно **только с тестового аккаунта владельца, номер которого заканчивается на 69**. Номер нигде не выводить.
- Получатели по умолчанию — только тестовые адресаты владельца (его собственные аккаунты из настроек рассылки).
- Отправка с тестового аккаунта настоящим бизнесам из «Лидов» — **только после явного «да» владельца в чате**, после того как ты покажешь названия и число получателей. Без этого — сухой запуск.
- Проверить всю цепочку: пачка → тексты → запуск → результат по каждому → повтор с напоминанием → исключение ответивших.
